Noosphera × Tabletop Simulator

Fluxo recomendado: no Squad Builder use Exportar deck TTS (folha PNG) — gera um ZIP com noosphera_deck_face.png (grelha de todas as fichas do esquadrão, com armas/tática/upgrades já reflectidos na HUD) e LEIA-ME_deck_TTS.txt com Width, Height e Number para colar no Custom Deck do TTS (documentação).

Opcional: o pacote Lua (global.lua, importador, NoospheraUnit) continua no repositório para mini-ficha em XmlUI nos modelos 3D — é mais frágil no motor do TTS.

Referência de técnicas (UI no TTS): mesas 40k / Yellowscribe.

1. Deck de cartas (fichas em imagem)

  1. No Squad Builder, monte o esquadrão (facção global, tática, upgrades, arma por modelo).
  2. Clique Exportar deck TTS (folha PNG) e guarde noosphera_tts_deck.zip.
  3. Aloje noosphera_deck_face.png num URL HTTPS (ou use ficheiro local se o TTS permitir).
  4. No TTS: Objects → Components → Custom → Deck, indique a imagem da Face e os valores Width, Height, Number do LEIA-ME_deck_TTS.txt.
  5. Defina um Back (verso único). Back is Hidden é opcional (ver KB).

Cada carta corresponde a uma unidade na ordem do painel do builder (em grelha: esquerda → direita, topo → baixo). Células vazias no fim da folha são preenchidas só para completar o rectângulo; Number é só o número de unidades.

2. Onde colocar cada script (opcional — Lua + XmlUI)

A. Script Global da mesa

  1. Abra a mesa no TTS (como host).
  2. Menu superior Games → Scripting (ou Host → Scripting, conforme versão).
  3. Aba Global → cole o conteúdo de global.lua → Save & Play.

Isso ativa onObjectHover para esconder/mostrar a mini-ficha ao mover o ponteiro entre objetos com tag noosphera_unit.

B. Objeto Importador (um por mesa)

  1. Objects → spawn algo neutro (ex.: Custom Token ou Block Rectangle) só como “cartão ferramenta”.
  2. Clique no objeto → ícone de engrenagem → Scripting.
  3. Cole NoospheraImporter.lua
    2
    no campo Lua.
  4. Aba UI (Xml UI) → cole NoospheraImporter.xml → salve (é só um <Panel /> vazio; evita XmlUI pesado no Importador).

C. Cada miniatura que terá ficha

Para cada modelo 3D (ou token) que representa uma unidade:

  1. Selecione o objeto → Scripting.
  2. Cole NoospheraUnit.lua em Lua.
  3. Na aba UI, cole NoospheraUnit.xml.
  4. Salve. Na primeira carga o script adiciona a tag noosphera_unit.

Sem esse Lua/Xml no objeto, o passo “Ligar seleção” do Importador falha (é esperado).

Se o TTS travar ou apagar o objeto ao Save & Play

O motor de XmlUI do Tabletop Simulator é frágil; o Importador usa XmlUI mínimo e dados na Description para não sobrecarregar o objeto. Gravar JSON enorme em Global também pode travar — por isso o squad fica só na memória do script do Importador (cached_squad), não no Global inteiro. Nas miniaturas, se ainda falhar, simplifica NoospheraUnit.xml ou testa outro tipo de objeto (Custom Token vs modelo Workshop).

3. Fluxo do pacote Lua (importação por dados)

O Importador usa dados na Description do token ou URL.

  1. Precisas de um JSON com units[] no formato que o NoospheraImporter.lua
    2
    espera (o Squad Builder já não gera este ficheiro; mantém-se só para quem quiser integração Lua manual ou tooling próprio).
  2. No TTS, selecione o token Importador → campo Description: cole o JSON ou uma URL que devolva esse JSON.
  3. Menu de contexto → Noosphera: carregar da DESCRIÇÃO.
  4. Selecione miniatura → Noosphera: LIGAR próxima unidade a SELECAO.

Reset: menu de contexto → Noosphera: resetar índice de ligação → 1.

4. UX Lua: mini-ficha vs ficha completa

Contexto Conteúdo exibido
Hover (mini) Nome, pontos, Noosphere, stats efetivos, loadout máx efetivo, arma escolhida
Botão “Ficha completa” Cabeçalho + bloco global + corpo com keywords, upgrades, habilidades

5. Contrato JSON legado (schema_version 1)

Usado apenas pelo importador Lua, não pelo export actual do Squad Builder:

Campo Descrição
schema_version 1
units[] Uma entrada por miniatura com name, weapon, stats / stats_effective, upgrades, etc.

Documentação completa dos campos ficou desactualizada em relação ao builder; o fluxo suportado para jogadores é o deck PNG.

6. Site estático (export Obsidian)

O Squad Builder precisa de tryInitSquadBuilder no site exportado: em navegação tipo SPA, scripts dentro do HTML injetado podem não correr; o motor é relançado a partir da textarea .js-sb-engine-script.

  • Custom head (export-fixes.md): cola no final do ficheiro o snippet em export-fixes-squad-builder-addon.md (só o bloco <script>...</script>, ou o ficheiro inteiro).
  • Variante legada: export-fixes.html ainda inclui o mesmo bootstrap junto com outros hacks — não mistures duplicado no export-fixes.md e outra cópia no mesmo <head> sem querer.

Mantém os ficheiros que precisares na lista de export do plugin Webpage HTML Export (settings do vault).

ZIP / CDN: export de ZIP e export de deck usam html2canvas e jszip via cdnjs; se a rede bloquear scripts externos, hospede cópias locais ou use outro browser.
